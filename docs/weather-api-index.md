## 文档覆盖范围

- 和风官方文档公开列出的全部 API 产品分类和接口入口。
- 彩云只整理当前套餐实际支持的综合、JSONP、实况、72 小时、逐日、历史 24 小时、预警和 4 项生活指数；套餐页逐日示例为 7 天，但实际返回上限仍需验证。
- 当前彩云套餐不支持的分钟降水、雷达和 v3 企业产品仅在排除清单中记录，不作为接入候选。
- 套餐或企业权限限制、版本状态、覆盖范围、时间与空间分辨率。
- 当前代码映射、数据源优先级、单位差异和禁止估算规则。

扩展产品的响应样例通常很大，本地文档保留 endpoint、能力摘要和官方详情链接，不复制整段官方 JSON；实现某项扩展产品前仍应重新核对其字段页。

## 当前项目的数据源顺序

当前实现不是“彩云优先”，而是和风作为基础数据源、彩云按字段增强：

1. 先用和风 GeoAPI 完成城市解析；坐标确定后，和风天气和彩云综合缓存并行读取。
2. `ENABLE_CAIYUN_API=false` 是默认值；未启用时只返回和风数据。
3. 和风分钟降水始终保留；彩云适配器不解析或融合 `result.minutely`。
4. 和风逐小时预报没有未来小时体感，使用彩云原生 `apparent_temperature` 按小时补全。
5. 所有重叠字段保持和风优先；彩云只补 `None`，并保留字段来源、降水类型和单位。
6. 和风天气失败但 Geo 成功时可用彩云兜底；普通城市名仍需要和风 GeoAPI 提供坐标。

代码入口：

- `services/fusion.py`
- `adapters/qweather.py`
- `adapters/caiyun.py`
- `domain/models.py`

## 已确定的成本策略

- 能由和风满足的命令和字段全部优先使用和风，因为和风当前免费。
- 彩云保持全局融合：所有实际天气入口读取同一个按坐标缓存的综合响应；订阅管理命令本身不调用天气 API。
- 彩云参与降雨任务的全局缓存读取，但不提供分钟数据；降雨判断仍以和风分钟和小时预报为主。
- 彩云按次数收费且当前有 10000 次额度：一次调用请求 `hourlysteps=72&dailysteps=15&alert=true`，原始响应缓存 3600 秒并进行进程内并发去重。
- 刷新按钮只强制刷新和风；彩云继续复用 1 小时缓存。
- 套餐页 `dailysteps=7` 是示例而非已证实硬上限；只有实测、合同或计费规则证明最多 7 日时才降为 7。

## 推荐的字段级优先级

不建议把某一家供应商无条件设为全部字段的主源。推荐按字段选择：

| 数据 | 首选 | 备用/补充 | 原因 |
| --- | --- | --- | --- |
| 城市与坐标解析 | 和风 | 彩云逆地理编码仅作扩展 | 和风 GeoAPI 支持全球城市、POI、重名与模糊搜索 |
| 实时基础天气 | 和风 | 彩云 | 当前模型、单位和展示主要按和风设计 |
| 实时体感 | API 原值 | 另一供应商原值 | 两家均有实时体感；缺失时不估算 |
| 未来小时体感 | 彩云 | 无 | 和风城市逐小时接口没有 `feelsLike` |
| 中国分钟降水 | 和风 `/v7/minutely/5m` | 小时预报降级 | 当前彩云套餐没有分钟级权限 |
| 海外分钟降水 | 小时预报降级 | 无分钟数据 | 和风分钟降水只支持中国，当前彩云套餐也无分钟权限 |
| 小时温度、风、湿度 | 和风 | 彩云字段级补缺或整体兜底 | 当前展示链路和缓存以和风为基础，合法零值不覆盖 |
| 小时空气质量 | 和风独立 v1 | 彩云套餐内小时块补充 | 和风提供未来 24 小时全污染物；彩云套餐内 72 小时块含 AQI/PM2.5 |
| 天气预警 | 和风 v1 | 彩云套餐内 v2 预警 | 和风覆盖全球；彩云套餐只确认了 v2 `alert=true` |
| 逐日预报 | 和风 | 彩云缓存结果补充 | 和风最长 30 天；彩云一次付费调用建议请求 15 日并以实际返回长度确认权益 |
| API 自然语言摘要 | 保留来源分别展示 | 不混成事实字段 | 文案是供应商结论，不应被当成原始观测值 |

## 禁止估算与缺失值规则

项目统一遵守以下规则：

- API 没有返回的数据必须保留为 `None` 或不展示，不能自动填 0、晴、无雨或其他看似合理的值。
- 不计算未来小时体感温度；只接受和风/彩云明确返回的原始体感字段。
- 不把实时温度复制为缺失的体感温度。
- 不根据 PM2.5 浓度猜测“首要污染物”。
- 当前彩云套餐不返回分钟数据，不能把它当成分钟降水来源。
- 官方编码表的确定性转换可以使用，例如预警代码到蓝/黄/橙/红、Pa 到 hPa；这属于单位/枚举转换，不是气象估算。
- 必须区分“字段缺失”和“官方返回零值”。
- 每个容易混淆的数值应携带供应商、单位和时间间隔，尤其是降水。

## 两家能力差异速览

| 维度 | 和风天气 | 彩云天气 |
| --- | --- | --- |
| 城市逐小时 | 24/72/168 小时 | 当前套餐 72 小时 |
| 未来小时体感 | 无 | 有原生 `apparent_temperature` |
| 逐日范围 | 3/7/10/15/30 天 | 套餐页示例 7 日；公开接口通常可请求 15 日，实际权益以响应长度为准 |
| 分钟降水 | 中国、每 5 分钟、5 分钟累计 mm、雨雪类型 | 当前套餐不可用；综合响应可能直接省略 `minutely` |
| 小时空气质量 | 独立 v1，未来 24 小时，多种污染物与健康建议 | 套餐内小时块含 AQI/PM2.5 |
| 历史天气 | 最近 10 天；更长期重分析需商务 | 套餐页面提供过去 24 小时 `begin=时间戳` 调用模板 |
| 预警 | 全球官方预警 | 套餐内 v2 `alert=true` |
| 生活指数 | 中国 16 类、海外 4 类 | 套餐内 4 类 |
| 其他产品 | 格点、台风、潮汐、太阳辐射、天文、控制台 API | 当前套餐未包含，不参与项目设计 |

## 当前项目实施状态

- 已完成彩云 1 小时原始响应缓存、single-flight、失败冷却和 `72h/15d/alert` 综合调用。
- 已完成 `mm`/`mm/h` 区分、Pa 转 hPa、风速/风力拆分、预警等级和禁止估算规则。
- 已接入彩云实况污染物/云量/能见度/辐射、小时体感/AQI/PM2.5，以及日级昼夜降水概率和 4 项生活指数。
- 已接入和风未来 24 小时与 3 日空气质量，并继续保持和风字段优先。
- 已按 profile 并行请求和风 endpoint；后台任务按唯一地点复用天气和 LLM 日报。
- 历史 24 小时、多容器 Redis 分布式锁和彩云套餐外产品仍不在当前实现范围。

## 维护约定

- 文档中的日期表示最后一次人工核对时间，不代表供应商以后不会调整。
- 实现新接口时，先更新对应本地文档，再修改模型、适配器、融合逻辑、格式化器和测试。
- 不在文档、日志、测试样例或截图中保存真实 API Key、Token、JWT 私钥或专属 API Host。
- 彩云文档只描述当前套餐范围；不能因为官方总目录存在某接口就假定当前 Token 有权限。
